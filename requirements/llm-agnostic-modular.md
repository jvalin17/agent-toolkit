# Requirements: LLM-Agnostic Modular Toolkit

> Generated by /requirements on 2026-10-12
> Mode: feature (existing agent-toolkit)
> Source: multi-model eval + Option B design (user confirmed)
> Project state: existing (agent-toolkit)

## Problem Statement

Skills and rules are too long for reliable LLM compliance. Multi-host support (Cursor, Gemini, Codex/GPT, Grok) is claimed but install/hooks remain Claude-centric. Non-Claude hosts get huge context dumps or missing scripts. Developers need a **short default path** plus **on-demand pull** of modules and deterministic gate functions, with the **orchestrator detecting the host LLM and loading the right configuration**.

## Core Requirement

Make agent-toolkit **LLM-agnostic and modular (Option B)**:

1. Detect which coding agent/host is running.
2. Load merged host configuration (`default` ⊕ host).
3. Inject a short bootstrap (core rules + skills index + host overlay).
4. Expose pull APIs for skill stubs, modules, roles, and `run_function` gates.
5. Keep skill stubs short; move depth into `modules/` and `functions/`.

## Boundaries

- **Does NOT** fork skills per LLM (one policy tree).
- **Does NOT** preload full role books or full skill bodies into `AGENTS.md`.
- **Does NOT** require paid APIs or cost routing changes (out of scope for this feature).
- **Does NOT** rewrite all 14 skills in v1 — stubify `implementation` + `precommit` first; others keep current files but are pullable as whole stubs until split.
- **Does** remain backward compatible for Claude Code hooks.

## One Thing This Must Do Well

**Orchestrator detects host → loads config → agent works from short default path and pulls depth only when needed — same development policy on every host.**

## Out of Scope (v1)

- Free-tier / cost optimization
- Full stubification of every skill
- Verified live integration against real Cursor/Gemini/Codex hook runtimes (fixtures + schema tests only)
- New marketplace plugins for non-Claude hosts

## User Stories

- As a Cursor/Gemini/Codex/Grok user, I get a short `AGENTS.md` (or host rules) with pull instructions, not an 80KB dump.
- As any host, I can `get_skill` / `get_module` / `run_function` via MCP or CLI.
- As a toolkit maintainer, I add a new LLM by adding `hosts/<id>.yaml` + detect signal + fixture test.
- As a developer, Fix/Build still means test-first and precommit-before-commit, enforced by hooks (structural hosts) or CLI functions (cli_only hosts).

## Functional Requirements

### F1: Host configuration

| ID | Capability | Priority |
|----|------------|----------|
| F1.1 | `hosts/default.yaml` shared policy | must |
| F1.2 | Per-host YAML: `claude-code`, `cursor`, `codex-cli`, `gemini`, `grok-build`, `windsurf` | must |
| F1.3 | Merge: default ⊕ host; unknown host → default + `id: unknown` | must |
| F1.4 | Schema keys: `id`, `rules_targets`, `skills_path`, `hooks`, `hooks_config`, `pull`, `stamp_mode`, `bootstrap` | must |

### F2: Detection

| ID | Capability | Priority |
|----|------------|----------|
| F2.1 | Existing detect (env/stdin/fs) loads host config | must |
| F2.2 | Add `gemini` to `SUPPORTED_AGENTS` + env/fs signals | must |
| F2.3 | Manual override `AGENT_TOOLKIT_TOOL` still wins | must |
| F2.4 | Prefer explicit env over filesystem (no `.claude` always winning when `CURSOR_*` set) — already env-first; document + test | must |

### F3: Pull API (MCP + CLI)

| ID | Capability | Priority |
|----|------------|----------|
| F3.1 | `resolve_host()` → merged config | must |
| F3.2 | `get_bootstrap()` → capped bootstrap text | must |
| F3.3 | `get_skill(name)` → stub + module catalog (names only) | must |
| F3.4 | `get_module(skill, module)` → one module file | must |
| F3.5 | `get_role(name, depth)` → compact\|checks\|full | must |
| F3.6 | `run_function(name, args)` → JSON pass/fail for registered functions | must |
| F3.7 | `stamp_skill(name)` for `cli_stamp` hosts | must |
| F3.8 | CLI entry: `python3 -m toolkit_mcp` tools and/or thin `scripts/toolkit_pull.py` | must |

### F4: Orchestrator

| ID | Capability | Priority |
|----|------------|----------|
| F4.1 | Plan includes `host`, `bootstrap` summary, `pull_policy` | must |
| F4.2 | `pull_policy`: stub_first skills, compact roles, modules on_signal, listed functions | must |

### F5: Short skills + rules

| ID | Capability | Priority |
|----|------------|----------|
| F5.1 | `rules/core.md`, `rules/skills-index.md`, `rules/hosts/<id>.md` | must |
| F5.2 | `implementation`: stub SKILL.md + modules (move current depth) | must |
| F5.3 | `precommit`: stub SKILL.md + modules | must |
| F5.4 | Stub ≤ ~80 lines / ~4KB guideline (test soft-warn or assert under 120 lines) | should |
| F5.5 | `generate-project-rules` script (replace missing doc reference) writes short AGENTS.md from bootstrap | must |

### F6: Functions (Option B gates)

| ID | Capability | Priority |
|----|------------|----------|
| F6.1 | `check_tdd_order` — reports whether TDD session state allows source edit | must |
| F6.2 | `gate_status` — reports missing precommit/evaluate stamps | must |

## Acceptance Criteria

1. `pytest` covers: merge config, each host YAML loads, gemini detect, get_skill stub, get_module, run_function, bootstrap cap, generate-project-rules output contains core rules and does NOT contain full precommit body.
2. `get_skill("implementation")` returns stub; modules listed; `get_module("implementation", "tdd")` returns content.
3. Adding a fake host fixture only requires new YAML + detect test (documented).
4. Claude Code path: existing hooks still pass current suite.
5. README / other-llms.md point at real `generate-project-rules` script.

## Scale / Users

Toolkit maintainers + developers using any supported host. v1 = developer tool quality, not SaaS scale.

## Concrete Examples

**Input:** `AGENT_TOOLKIT_TOOL=cursor` + `resolve_host()`  
**Output:** `{id: cursor, hooks: structural|…, rules_targets: [AGENTS.md, .cursor/rules/toolkit.mdc], …}`

**Input:** `get_skill("precommit")`  
**Output:** stub markdown + `modules: ["checks", …]` — not 346-line body

**Input:** `generate-project-rules.sh` in empty project  
**Output:** `AGENTS.md` with core + pull instructions + skills index; file size well under previous full-depth dumps
